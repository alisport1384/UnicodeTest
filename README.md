# P6TX Lab

اپ مرورگری برای مقایسهٔ حجم و زمان بازخوانی UTF-8 با کدگذاری اختصاصی P6TX. فایل‌های `.txt` و `.md` معتبر UTF-8 (حداکثر ۸ مگابایت) پشتیبانی می‌شوند. داده به سرور ارسال نمی‌شود.

## اجرا

فایل `index.html` را در یک مرورگر مدرن باز کنید؛ یا در پوشهٔ پروژه `python3 -m http.server 8000` را اجرا و `http://localhost:8000` را باز کنید. Node.js 20 یا جدیدتر برای تست و ساخت لازم است:

```sh
npm test
npm run build
```

فایل‌های ساخته‌شده در `site/` قرار می‌گیرند. در GitHub Actions بعد از اجرای موفق، artifact با نام `p6tx-lab-site` برای دانلود موجود است. برای نمایش آنلاین می‌توان محتوای پوشهٔ سایت را روی هر میزبان فایل ایستا منتشر کرد.

## روش آزمایش

فایل ابتدا در حافظه خوانده می‌شود؛ زمان خواندن از دیسک اندازه‌گیری نمی‌شود. اندازهٔ P6TX شامل ۱۷ بایت سرآیند است. صحت با مقایسهٔ کامل بایت‌ها و CRC بررسی می‌شود. سپس زمان تبدیل UTF-8 خام به رشتهٔ جاوااسکریپت در برابر دیکد P6TX، کنترل CRC و تبدیل نتیجه به رشته اندازه‌گیری می‌شود. هر مسیر دو بار گرم می‌شود و سپس میانهٔ ۷ نوبت گزارش می‌شود؛ هر نوبت ممکن است چندین تکرار داشته باشد. سرعت با تقسیم اندازهٔ UTF-8 خروجی بر زمان محاسبه می‌شود و MB برابر یک میلیون بایت است. نتایج به مرورگر، پردازنده و محتوای متن وابسته‌اند. ممکن است P6TX بزرگ‌تر و کندتر باشد. خروجی JSON اطلاعات محیط و زمان‌های نمونه را دارد.

## قالب

P6TX نسخهٔ ۱ با جدول ثابت ۶ بیتی برای ۶۳ نویسه و فرار برای سایر نقاط کد Unicode، متن UTF-8 معتبر را بدون تغییر بازیابی می‌کند. سرآیند ۱۷ بایتی شامل magic، نسخه، تعداد بیت‌های payload و CRC32 است. کد `codec.js` و بردار آزمایشی `سلام` مشخصات اجرایی قالب را نشان می‌دهند. CRC برای کشف خطای تصادفی است و امنیت یا اصالت داده را تضمین نمی‌کند.

## Android APK

در GitHub Actions، artifact به نام `P6TX-Lab-Android-APK` حاوی فایل `app-debug.apk` قابل نصب است. حداقل نسخه Android 8 (API 26) و WebView به‌روز لازم است. برنامه کد native ندارد، بنابراین APK عمومی آن بر روی `armeabi-v7a` و دیگر معماری‌های مورد پشتیبانی اندروید قابل نصب است. فایل debug با کلید debug خودکار امضا می‌شود و نسخهٔ انتشار فروشگاهی نیست. برنامه بدون دسترسی شبکه کار می‌کند؛ انتخاب فایل و ذخیرهٔ گزارش با انتخاب‌گر Android انجام می‌شود. عملکرد واقعی روی دستگاه باید جداگانه بررسی شود.

## سند طراحی

[سند طراحی فارسی P6TX](docs/P6TX-design-fa.md) جزئیات قالب، جدول کد، الگوریتم، محدودیت‌ها و نتایج آزمایش اولیهٔ نمونهٔ پایتون را شرح می‌دهد. برای بازتولید همان آزمایش اولیه: `python3 docs/test_design.py`. این نتایج مربوط به نمونهٔ پایتون هستند، نه بنچمارک مرورگر یا دستگاه اندرویدی.

## بهینه‌سازی بازخوانی

دیکدر JavaScript در نسخهٔ اپ ۱٫۱ بدون تغییر قالب P6TX بهینه شده است. کد جدول پیش‌محاسبه می‌شود و خروجی داخل یک بافر نوشته می‌شود. آزمایش تطبیقی و داده‌های عملکرد محلی در [بخش ۱۵ سند](docs/P6TX-design-fa.md) آمده است. برای مقایسهٔ محلی: `node scripts/benchmark-decode.js`. عملکرد گوشی را باید با خود گوشی اندازه‌گیری کرد. گزارش جدید `decoder_version` دارد.

## پروفایل مرحله‌ای (اندروید ۱٫۲)

اپ پس از آزمون اصلی، دیکدر تشخیصی جداگانه را اجرا و زمان تقریبی حلقه، فرار، CRC و تبدیل متن را به‌همراه تعداد فرارها در صفحه و گزارش JSON نمایش می‌دهد. این اجرا سربار ابزار دارد و جای عدد زمان اصلی بدون ابزار را نمی‌گیرد. تعریف مراحل و محدودیت‌ها در [بخش ۱۶ سند](docs/P6TX-design-fa.md) آمده است. این نسخه به‌منظور اندازه‌گیری است، نه ادعای بهبود عملکرد نسبت به نسخهٔ ۱٫۱.

## بهینه‌سازی مسیر فرار (اندروید ۱٫۳)

مسیر فرار بدون تخصیص آرایه و TextDecoder به‌ازای هر کاراکتر، با اعتبارسنجی سخت‌گیرانهٔ UTF-8 پیاده‌سازی شد. قالب و CRC بدون تغییرند. آزمون‌های تطبیقی و بنچمارک محلی در [بخش ۱۷ سند](docs/P6TX-design-fa.md) آمده است. برای مقایسهٔ مصنوعی: `node scripts/benchmark-escape.js`. نتایج گوشی باید با گزارش جدید سنجیده شود.

## اندازه‌گیری مستقل CRC و دیکد (اندروید ۱٫۴)

نسخهٔ ۱٫۴ دیکد بدون CRC، CRC مستقل، تبدیل UTF-8 و مسیر کاملِ دارای CRC را جداگانه زمان‌سنجی می‌کند. مسیر بدون CRC صرفاً ابزار بنچمارک است و دیکدر معمولی همچنان بررسی CRC را اجباری انجام می‌دهد. توضیح روش، محدودیت‌ها و نتایج محلی در [بخش ۱۸ سند](docs/P6TX-design-fa.md) آمده است. بنچمارک محلی: `node scripts/benchmark-crc.js`.

## نتیجهٔ تست دستگاه نسخهٔ ۱٫۴

طبق گزارش کاربر، برای ورودی ۷۲٬۸۳۱ بایتی، حجم P6TX برابر ۴۰٬۸۷۸ بایت و زمان میانهٔ بازخوانی کامل ۶٫۹۷۵ میلی‌ثانیه بود؛ UTF-8 معمولی ۱٫۷۷۸ میلی‌ثانیه طول کشید. شرایط مقایسه، سرعت نسخه‌های قبلی، آزمون‌های مستقل و محدودیت‌ها در [بخش ۱۹ سند](docs/P6TX-design-fa.md) ثبت شده‌اند.

## عکس و انگلیسی (اپ ۱٫۵)

از پیوند «آزمایش عکس و انگلیسی» می‌توان فایل انگلیسی UTF-8 یا JPG/PNG را آزمایش کرد. P6TE جدول انگلیسی جداگانه با magic مجزا است؛ IMX1 تصویر را با gzip بدون‌اتلاف یا خام (هر کدام payload کوچک‌تری داشته باشد) ذخیره و با CRC و مقایسهٔ بایت‌ها تأیید می‌کند. هر دو حالت سرآیند دارند و کاهش حجم عکس تضمین نمی‌شود. **packJPG در این APK نیست**؛ آزمایش قبلی آن فقط در Linux انجام شده است. [جزئیات فرمت، تست و محدودیت‌ها](docs/P6TX-design-fa.md) در بخش ۲۰ است.
